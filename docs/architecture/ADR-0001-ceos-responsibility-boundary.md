# ADR-0001: CEOS の責任範囲（工程・原価・契約の正本）とシステム間境界

- **状態**: Proposed（承認待ち）
- **日付**: 2026-09-20
- **対象リポジトリ**: Construction-Enterprise-OS（CEOS）
- **根拠文書**: 「みらい建設土木DX・AI統合基盤 全体構成 **V3.5**」（`docs/みらい建設土木DX・AI統合基盤 全体構成 V3.5.html`）

## 背景

評価により「CEOS が全業務・全データの統合主体を掲げているが、V3.5 では CEOS は工程・原価・契約の正本であり、統合入口・承認・証跡は MCIP、文書の正本は CDE が担う」という役割の不一致が指摘された。実装・運用の重複を避けるため、CEOS の責任範囲と他システムとの境界を本 ADR で確定する。

## 決定

### 1. CEOS が正本を持つもの

- **工程・原価・契約**（V3.5 §3 データ所有マトリクス）。
- 数量・出来高の**最終確定は CEOS 側で人が承認**する（AI は確定しない）。

### 2. CEOS が正本を持たないもの（他システムが正本）

| データ                                                         | 正本                      | CEOS の扱い                   |
| -------------------------------------------------------------- | ------------------------- | ----------------------------- |
| 案件コンテキスト（案件ID・関係者・文書索引）                   | MCIP                      | 参照（案件IDは MCIP が発番）  |
| 承認記録・監査証跡・AI回答記録                                 | MCIP（追記専用）          | 参照                          |
| 図面・文書・写真（確定版）／成果物                             | CDE（DirectCloud／M365）  | 参照（原本を複製しない）      |
| BIM/CIM・点群・GIS 空間モデル                                  | ArcSphere Civil Twin      | 参照                          |
| 公開データ台帳・海象／気象                                     | CODIP                     | 参照（判定結果の記録は MCIP） |
| ポリシー・証跡スキーマ・承認階層・モデルルーティング・Tool契約 | Mirai-Harness-Core（Git） | 参照（再実装しない）          |

### 3. 統合入口と連携方式

- **統合入口は MCIP のみ**。CEOS は他システムと**公開 API（MCP サーバー公開）**で連携し、正本の重複を避ける。
- CEOS は自前の全社承認基盤・AI 統制基盤を再実装しない。

### 4. AI の扱い

- CEOS は**モデル鍵を保持せず**、AI 呼出しは MCAH（Tool Gateway 経由のみ）に委譲する。機密区分・承認・証跡は MCAH/MCIP 側で一貫管理する。
- 本番のモデル提供元は **OpenAI／Anthropic に限定**（V3.5 §2.1）。ローカル LLM は使わない。
- 承認階層 **R0〜R4** を前提とし、**R4（本番DB直接更新・最終確定・無承認RSI・極秘のモデル送信）は恒久的に拒否**する。
- 実効権限は「利用者 ∩ Agent ∩ Skill ∩ Tool ∩ 案件Policy ∩ データ品質条件 ∩ 機密区分で許可されたモデル」の積集合（V3.5 §5.2、二重認可）。

### 5. CEOS 内の実装判断

- 認可は **組織（テナント）＋案件（project）＋ロール**で行い、API 到達性は公開 API の契約に従う。
- 本番構成は V3.5 の段階（CEOS＝第2段階）に従い、必須サービスに絞る。

## 結果（Consequences）

- **正**: 正本の重複がなくなり、承認・証跡・AI統制の再実装を避けられる。CEOS の投資は「工程・原価・契約の正確性」（変更契約・請求漏れ防止等）に集中できる。
- **負**: CEOS 単体では全社統合を完結できない。MCIP／CDE／ArcSphere／MCAH との連携契約（API・証跡・版）が必要。
- **要対応**: 連携契約の版管理、Core 契約の固定参照を CI で検証する仕組み（別途）。

## 未決・確認事項

- MCIP／MCAH／Harness Core の実装状況と API 契約の具体（別リポジトリ）。
- 案件メンバーシップ（project 単位の権限）のモデル定義。
- 本 ADR は V3.5 を正とするが、V3.5 内の「リポジトリ数」「配置」等の記述ゆれは別途整理する。
