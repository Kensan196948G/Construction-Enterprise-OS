# 要件と OpenDesign の整合(MVP スコープ)

> OpenDesign 設計仕様(docs/design/opendesign-spec.md)と実装の整合マッピング。
> 完了条件「主要業務フローが OpenDesign の目的と整合し、実際に操作可能」の根拠。

## 1. MVP の定義

- **フロントエンド**: OpenDesign 設計プロトタイプ(単一HTML React SPA)を
  Cloudflare Pages(`construction-os-mvp` / `construction-os-web`)で配信
- **バックエンド**: auth サービス(FastAPI)+ Neon PostgreSQL を
  Pages Function プロキシ + Cloudflare Tunnel で HTTPS 公開
- **データ**: 設計プロトタイプ内の有効なダミーデータ(正常・空・エラー・権限別状態)+
  Neon シードデータ(2組織/1ユーザー/7ロール/43権限)

## 3. ロール別の検証状態(E2E)

| ロール | 検証 |
|---|---|
| 全表示(管理者) | ✅ E2E: ダッシュボード・サイドバー全カテゴリ |
| 現場監督(field) | ✅ E2E: ロール切替で「現場監督ビュー」表示 |
| 経営層(exec) | ✅ E2E: ロール切替で「経営層ビュー」表示 |
| その他(partner/safety/maintain) | ✅ ロールメニューに存在・フィルタ動作はコード検証 |

## 4. 正常・空・エラー・権限別状態

| 状態 | 実現方法 | 確認 |
|---|---|---|
| 正常 | ダミーデータ(KPI・一覧・タブ) | ✅ E2E |
| 空 | データ無しセクション(空状態表示) | ✅ コード確認(E2E 対象外の空ビューは次回追加) |
| エラー | API エラー(401/422 等)は auth API で実証 | ✅ HTTPS API 検証 |
| 権限別 | ロールフィルタ(サイドバー)+ API の JWT 認可 | ✅ E2E + API 検証 |

## 5. 未実装・差分(残存リスク)

1. WebUI のダミーデータ → auth API 実データへの接続(画面のログイン/ユーザー一覧を実データ化)
2. ルーティングの URL 同期(state ベース → 次フェーズの Next.js 実装で解消)
3. サイドバーのポインター横取り問題(z-index 修正)
4. トンネル直接 HTTPS(証明書パック発行権限のトークンが必要)
